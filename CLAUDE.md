# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

paraText adds audience-targeted context to technical text. It has two parts:
- **PDF reader** (main feature, added 2026-10, Qt/PySide6 since 2026-11). It underlines terms in scientific-paper
  PDFs and shows hover explanations generated by whichever AI provider the user configures. It is provider-agnostic
  on purpose: the user wants it to work with their own subscriptions, not only Claude.
- **`ParaText` widget**: the original 2022 course project, kept as a legacy proof of concept. It is a `tk.Text`
  whose underlined spans offer right-click replacement options. Don't build new features on tkinter.

**Read `notes/roadmap.md` (open items and what to do next), `notes/ReportedIssues.md` (issues the user logged
from inside the reader while testing; address the ones with `Status: open` and update their status) and
`notes/dev_log.md` (decisions and history) before starting work.** Add to the roadmap and dev log when you finish
a chunk of work.

## Commands

```sh
.venv/bin/pip install -e ".[dev]"         # a project-local .venv (gitignored) was used during development
python -m pytest                           # ~145 tests, ~8s; Qt tests run offscreen, Tk tests skip without a display
python -m pytest tests/test_engine.py::test_cache_round_trip   # single test
pre-commit run --all-files                 # check-yaml, end-of-file, trailing-whitespace, ruff (v0.6.4 pinned)
ruff check . && ruff format .              # line length 120; rules pinned in pyproject (UP038 ignored)
paratext read paper.pdf [--provider NAME]  # GUI
paratext setup                             # just the AI setup dialog
paratext glossary paper.pdf --provider none --json   # headless; `none` = offline (acronyms only)
paratext ask paper.pdf "question"          # whole-paper question (full text in the prompt), headless
paratext providers [--check]               # readiness of every provider (+ a test prompt for configured ones)
paratext install-app                       # macOS: write ~/Applications/paraText.app (Finder "Open With" for PDFs)
```

Test style matches the user's other repos (crawfish, cvtypecorr): plain pytest functions in `tests/test_*.py`,
fixtures in `tests/conftest.py` (`tk_root` skips without a display; it also sets `QT_QPA_PLATFORM=offscreen`
before any `QApplication` exists), and shared helpers in `paratext.testing` (`FakeProvider`, `make_sample_pdf`,
synthetic click helpers). Qt tests use pytest-qt (`qtbot`, `QTest.mouseMove/mouseClick` on `view.viewport()`).
CI (`.github/workflows/tests.yml`) runs pre-commit plus pytest on Ubuntu, macOS and Windows with Python 3.10 and
3.12; Linux installs the libraries PySide6 links against and a virtual display for the Tk tests.

## Architecture (reader)

Data flows `pdf.py` → `glossary.py` / `ai/` → `engine.py` → `reader/` (and `cli.py`).

- **`pdf.PdfDocument`** (PyMuPDF) holds words with boxes in **content-stream order**. Don't use `sort=True`: it
  interleaves two-column layouts. Ligatures are expanded at extraction. Coordinates are PDF points from the top-left.
  PyMuPDF is not thread-safe, so every `_doc` access takes `self._lock`; the GUI's render thread and the engine's
  workers share one document. `render(page, scale)` returns raw RGB for Qt; `render_png` is for scripts.
- **`glossary.py`**:
  - `parse_terms` reads model JSON robustly (code fences, prose around it).
  - `extract_acronyms` finds "long form (ACR)" definitions offline.
  - `find_spans` locates terms among page words: case-insensitive, edge punctuation stripped, NFKC, joins
    line-end hyphenation, and the longest match wins. Terms are keyed by `normalize_term`, which lowercases
    except for short capitalized single tokens (≤4 chars: "FE", "Fe", "pH", "DFT"); those keep their case and
    match exactly (`is_case_sensitive`), so an acronym is not underlined at an element symbol.
  - `GlossaryEntry.provider`/`proofread` record the provider cache key that wrote / checked an entry;
    `parse_corrections` reads the proofreading reply (keep/fix/remove per term).
- **`ai/providers.py`**: `Provider.complete(system, prompt, json_schema=None) -> str`. There are three kinds:
  - `OpenAICompatibleProvider` (stdlib urllib). It covers OpenAI, Gemini's OpenAI endpoint, OpenRouter, Ollama and
    LM Studio.
  - `AnthropicProvider` (official `anthropic` SDK, an optional extra). It uses `client.beta.messages.create`,
    defaults to `claude-opus-5-5` with `output_config.effort="low"`, and sends `output_config.format`
    (json_schema) when a schema is given. For models in `_FALLBACK_MODELS` it adds
    `fallbacks="default"` + beta `server-side-fallback-2026-07-01`. `stop_reason == "refusal"` raises.
  - `CommandProvider` (subprocess, prompt on stdin). These are the "subscription" presets:
    `claude -p`, `codex exec -`, `gemini`. `model_args`/`effort_args` templates add the tool's flags;
    `claude-cli` has both (`--model X --effort Y`, verified live 2026-11-04 with Claude Code 2.1.318).
    `probe_claude_models` runs a one-word prompt per alias (`fable`, `opus`, `sonnet`, `haiku`) with
    `--output-format json` and reads `modelUsage` to learn the resolved ids ("Check models" in the dialog).

  `PRESETS` + `make_provider(name, settings)` build providers from config. Every failure becomes a
  `ProviderError`, which the GUI/CLI show to the user. `PRESET_INFO` (titles, descriptions, suggested models),
  `preset_status` (is a CLI installed / is a key or model set, without calling anything), `list_models`
  (`GET /models` on OpenAI-compatible servers) and `provider_capabilities(settings)` (which fields a provider
  kind supports: key, server URL, model, model listing, effort levels, command) feed the setup dialog and
  `paratext providers`. Effort is `output_config.effort` for Anthropic and `reasoning_effort` (blank = not sent)
  for OpenAI-compatible servers; subscription CLIs take a model through the preset's `model_args`
  (`claude -p --model X`, `codex exec -m X`, `gemini -m X`; flags unverified live). Model and effort are part of
  `cache_key`.
- **`ai/prompts.py`**: all prompt text plus `PROMPT_VERSION`. Bump it when the wording changes; it is part of the
  cache key. `system_prompt(audience, reader_profile)` appends the profile paragraph.
- **`profile.UserProfile`**: the reader's local profile (`background`, `specialties`, `known`, `needs_help`,
  `notes`), TOML at `$PARATEXT_PROFILE` or `~/.config/paratext/profile.toml`. `to_prompt()` is appended to the
  system prompt, `known` concepts are passed to the glossary prompt as needing no entry, and `fingerprint()` is
  part of the engine's cache key. Only the user writes it in v1; `notes/user_profile_design.md` describes how
  questions will feed it later.
- **`engine.ContextEngine`** builds the glossary **per page**. Each request includes the paper context (title + start
  of page 1) and the list of already-known AI terms, to avoid duplicates. The spans for a page are computed from the
  *whole* glossary, so a term found on page 2 is also underlined on page 7. AI entries replace offline acronym
  entries but never other AI entries. Explanations of arbitrary phrases are cached by `brief|detailed`, page and
  normalized phrase.
  - Persistence: JSON in `cache_dir/<sha256[:16]>-<sha1(provider.cache_key|audience|PROMPT_VERSION)[:10]>.json`.
  - Jobs run on a 2-worker `ThreadPoolExecutor`, with duplicate in-flight requests suppressed. Callbacks run on the
    worker thread. Tests and the CLI use `ImmediateExecutor` for synchronous runs.
- **`reader/pageview.DocumentView`** (QGraphicsView): all pages stacked in one scene, in PDF points; zoom is the
  view transform, so overlays need no zoom math. Each `PageItem.paint` asks `PixmapCache.get(page, scale)` for a
  pixmap at the effective scale (view zoom × devicePixelRatio, capped at 4); misses are rendered by `_RenderJob`
  on a 1-thread `QThreadPool` and the item repaints when `_RenderSignals.done` arrives, drawing any older-scale
  pixmap meanwhile. Underlines/hover/selection are drawn in `paint` with cosmetic pens. `PageItem` does hover
  hit-testing (`span_at`) and word selection (`doc.word_at`), and reports through the view's signals
  (`termHovered`, `termClicked`, `selectionChanged`, `currentPageChanged`, `visiblePagesChanged`). The current page
  is the one with the largest visible area; `go_to` overrides it so navigation works when all pages fit.
- **`reader/app.ReaderWindow`** (QMainWindow): toolbar, the view, and a side panel (info bar for "no AI", title,
  body, footer, buttons). Engine callbacks run on worker threads; they call `EngineSignals.*.emit`, and Qt delivers
  the slots on the GUI thread. Term spans per page are recomputed lazily (`_ensure_spans`) when
  `_glossary_version` changes. Visible pages plus the next one are requested as you scroll; "Explain whole paper"
  queues every page. Hover explanations are `reader/popup.ExplanationPopup`, a frameless
  `ToolTip`-type window with explicit colours that stays open until another term is hovered, the viewport gets
  a click/wheel/key (event filter), Escape, or the window deactivates. `QToolTip` auto-hid after a second or so
  (reported issue, 2026-11-04). `TOOLTIP_STYLE` still styles ordinary widget tooltips.
- **`reader/setup.SetupDialog`**: list of options (presets grouped as subscription / API key / local, plus custom
  entries) with a readiness mark, a form whose rows and choices come from `provider_capabilities`, "Fetch
  models", "Send a test prompt" (both on `QThreadPool` with `_JobSignals`), and "Save and use", which validates
  with `make_provider` and writes the config. It edits a deep copy of the config; the window adopts
  `dialog.config` on accept. `reader/profile_dialog.ProfileDialog` edits the reader profile the same way
  ("About you…" in the toolbar); the window saves it and rebuilds the engine.
- **`links.py`**: `LinkStore` keeps files linked to a paper (`Link(path, kind pdf|data|folder, label, added,
  description, description_by)`) in `$PARATEXT_LINKS` or `~/.config/paratext/links.json`, keyed by
  `PdfDocument.sha256`. PDF links are reciprocal (the linked PDF's hash gets a link back to the paper; `remove`
  undoes both). `link_context(links)` renders `<linked_file>` blocks for prompts (PDF text, small text files,
  folder listings, a note for binaries; shared budget), `link_sample` a short sample for `describe_link_prompt`.
  The engine takes `link_store=` and uses it in `ask_job` (the question cache is keyed with a fingerprint of the
  links) and `describe_link_job` (auto-run by the window when a file is linked; "Describe…" sets a user one).
  `ReaderWindow.open_in_new_window` opens a linked PDF in a second window kept in `_child_windows`. Tests get an
  isolated links file from an autouse conftest fixture.
- **`issues.py`**: the reader's "Log an issue" box. `log_issue(note, IssueContext, provider)` always appends the
  verbatim note plus context (paper, page, provider, audience, panel title) to `notes/ReportedIssues.md` (found
  through `repo_root()`: the `pyproject.toml` above the package, i.e. an editable install; else
  `~/.config/paratext/`; `$PARATEXT_ISSUES` overrides). With a provider it first asks for a JSON
  title/category/description (`prompts.issue_prompt`, `ISSUE_SCHEMA`); provider failures are noted in the entry,
  never raised. The window runs it on `QThreadPool` (`_IssueJob`) and reports in the status bar.
- **`macapp.py`**: writes the macOS bundle (`Info.plist` claiming `com.adobe.pdf` at rank Alternate, a shell
  launcher that `exec`s `sys.executable -m paratext read` with the installer's `PATH` baked in, output to
  `~/Library/Logs/paraText.log`, an icon drawn with QPainter + `iconutil`), then registers it with `lsregister`.
  Finder hands files over as Apple Events, so `reader/app.FileOpenHandler` (an event filter installed by `run()`)
  opens `QFileOpenEvent` files; the launcher passes no argv. Verified live on 2026-11-03 with `open -a`.
- **`config.py`**: TOML at `$PARATEXT_CONFIG` or `~/.config/paratext/config.toml`; the cache is at
  `$PARATEXT_CACHE_DIR` or `~/.cache/paratext`. A missing config means offline mode. `Config.save()` writes the
  file (0600, comments dropped; `tomli-w`); the window saves on provider/audience changes. `paratext config --init`
  writes a commented template.

## Architecture (legacy widget, `widget.ParaText`)

All state is in tk tag names:
- `_REP_<pattern>`: a parent tag, used only as a dict key.
- `_REP_<id>_CNT_<True|False>_SNC_<pattern>`: a child tag, one per occurrence.
- `_ISO_<pattern>`: a standalone span. This is half-implemented: nothing creates these tags.

`replace_tags` maps parent → options; `rep_replace_tags` maps parent → children. Toggling sync renames the child tag
and rebinds the whole family (`setup_rep_bind_tag`). `textutils.replace_tagged_text` inserts the new text carrying the
old text's tags, then deletes the old range. Right-click is Button-2 on macOS (aqua) and Button-3 elsewhere
(`ParaText.right_button`, `testing._right_button`).

## Gotchas

- `PdfDocument.word_at` and `PageItem.span_at` are linear scans. That's fine at ~1k words per page.
- `paratext.testing` imports PyMuPDF lazily (only in `make_sample_pdf`), so widget-only users don't need it.
- The IDE's Python may not be the project `.venv`, so Pyright may flag `PySide6` imports as unresolved. Use
  `.venv/bin/python`.
- `QFormLayout.setRowVisible(widget, bool)` hides rows; tests check `widget.isHidden()` (not `isVisible()`).
- Anthropic model IDs and API shapes come from the `claude-api` skill (cached 2026-10). Check the skill again before
  changing `AnthropicProvider`; don't rely on memory.
